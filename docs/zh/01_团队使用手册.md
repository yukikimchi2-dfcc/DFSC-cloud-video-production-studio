# 团队使用手册

适用对象：Editor、Motion Designer、Reviewer、Admin。所有操作都在云端环境完成（Claude Code 云端会话或 GitHub Codespaces），不需要任何人的电脑。

> 任何时候都可以直接请 Claude Code 代为执行下列步骤，例如：「帮我为 dfsc-2027 生成 Preview 并提交审核」。

---

## 0. 每次开工

**开 Claude Code 云端会话时**：仓库选 `yukikimchi2-dfcc/DFSC-cloud-video-production-studio`，分支选 `claude/cloud-ai-video-studio-setup-utp2z3`（合并到 main 之前），环境选 Default。同一个 group 不会自动继承规则或对话，规则来自所选分支里的 [CLAUDE.md](../../CLAUDE.md)。第一条指令见 [CONTINUE_SETUP.md](../../CONTINUE_SETUP.md) §3。

```bash
git pull                      # 取得最新代码与项目状态
studio audit --offline        # 环境检查（字体、FFmpeg、套件）
studio project list           # 所有项目与状态
studio project status <项目ID> # 读这个项目的交接说明（HANDOVER.md）
```
收工前：**一定要 `git add` → `git commit` → `git push`**。云端容器是临时的，没推上 GitHub 的东西会消失。

## 1. 如何开始新项目

```bash
studio project new meta-leads-2027q1 --name "2027 Q1 Meta Leads 广告" --type meta_leads --brand-from dfsc-2027
```
- 会建立 `projects/meta-leads-2027q1/`：`project.yaml`、`brand/`（从 dfsc-2027 复制品牌包；不加 `--brand-from` 则是空白模板）、`HANDOVER.md`、`activity.jsonl`。
- 新品牌：编辑 `brand/brand.yaml` 的颜色、字体、Logo。客户提供 `.ai` 主视觉时可用
  `studio brand extract 主视觉.ai projects/<ID>/brand/logos --groups groups.yaml` 提取矢量 Logo（参考 `projects/dfsc-2027/brand/source/groups.yaml`）。
- 渲染规格不同（例如 1:1、4:5）：在 `project.yaml` 的 `overrides:` 覆盖 `config/defaults.yaml`。
- 开工：`studio project status <ID> --set "In Progress" --role Editor`

## 2. 如何上传素材

1. 把原始素材放进 Google Drive：`Cloud Video Production Studio/02_Source_Materials/...`，或项目文件夹 `05_Active_Projects/<项目>/`。
2. 建立索引（只读元数据，不复制）：
   `studio drive scan --folder <文件夹ID> --label "<项目>素材" --brand <品牌>`
3. 需要渲染时系统会把素材下载到 `workspace/`（断点续传 + MD5 校验），你不用手动下载。
4. 在 `project.yaml` 的 `handover.assets` 记录用到的素材（或 `studio project handover <ID> --asset "interview_A.mp4"`）。

**禁止**：删除或移动 Drive 原始文件；把影片提交到 GitHub（`.gitignore` 已阻挡 `*.mp4`、`*.mov`）。

## 3. 如何选择模板

```bash
studio templates list                         # 列出所有模板（ID、版本、类别）
studio templates preview title_card_impact --project <项目ID> --out workspace/preview_tc
```
- 每个模板文件夹 `templates/<ID>/` 有 `preview.png`、`preview.gif`、`template.yaml`（中文说明 + 所有可调参数）。
- 模板只使用**颜色角色**（primary / background / text…）与**字体角色**，所以套到不同项目会自动换成该项目的品牌。
- `review_status: UNREVIEWED` 的模板可以试用，但正式影片应使用 `APPROVED` 的模板（由 Reviewer 批准）。
- 记录：`studio project handover <ID> --template "title_card_impact@1.0.0"`

在代码中使用：
```python
from studio.motion.templates import build_template
layers = build_template("title_card_impact", {"text": "創業就是現在", "color": "primary"}, brand, start=3.0)
timeline.add(*layers)
```

## 4. 如何修改字幕

字幕流程：转写 → 自动断句 → 人工修改 → 烧入。
```python
from studio.edit.transcribe import transcribe, Transcript
from studio.edit.subtitles import cues_from_transcript, write_subtitles, read_srt, SubtitleLayer
tr = transcribe("workspace/interview.mp4")                 # 需要 Whisper 模型（见 SETUP_AUDIT 阻碍 #2）
tr.save("projects/<ID>/edit/transcript.json")
srt, ass = write_subtitles(cues_from_transcript(tr), "projects/<ID>/edit/subtitles")
```
- **人工修改**：直接编辑 `projects/<ID>/edit/subtitles.srt`（任何文本编辑器，或 GitHub 网页）。改错字、改断句、调整时间码都可以。
- 读回修改后的字幕：`cues = read_srt("projects/<ID>/edit/subtitles.srt")`，再 `SubtitleLayer(cues)` 加到时间轴。
- 每行字数、行数、繁体输出在 `config/defaults.yaml` 的 `subtitles:`，可在项目 `overrides` 修改。
- 字幕样式（字号、颜色、高亮色、描边）是 `SubtitleLayer(cues, size=68, color="text", highlight="primary", stroke_width=6)` 的参数。
- QC 会检查字幕是否超出安全区。

## 5. 如何修改 Motion Graphics

- **改参数**（最常见）：只改 `build_template(..., {参数})` 里的值，参数清单见 `templates/<ID>/template.yaml`。
- **改模板本身**（Motion Designer）：模板 builder 在 `studio/motion/templates.py`（`@register("<ID>")`）。修改后：
  1. 把 `template.yaml` 的 `version` 加一（例如 1.0.0 → 1.1.0），说明改了什么；
  2. `python tools/demo_motion.py --previews` 重新生成预览；
  3. `python3 -m pytest tests/test_motion_templates.py`；
  4. 建 Pull Request，请 Reviewer 看 `preview.gif`。
- **新模板**：新增 `templates/<新ID>/template.yaml` + builder，同上测试。
- 积木：`studio/motion/` 下的 `typography`（文字动画）、`cards`（卡片）、`camera`（运镜）、`transitions`（转场，时长以**帧**为单位）、`particles`（星芒/粒子/暗角）、`stickers`（贴纸）。所有座标以 1080×1920 设计像素编写。

## 6. 如何生成 Preview

```bash
studio queue add --builder <模块>:<函数> --kwargs '{"...": "..."}' --mode preview --name <项目ID> --project <项目ID> --chunk 2
studio queue run            # 执行；失败自动重试 3 次，日志在 workspace/queue/<job>.log
studio queue list           # 查看进度
```
- Preview：720×1280、H.264、自动控制在 30 MB 以下。
- 只渲染一段：`studio queue add ... --start 12 --end 18`；或用 `--chunk 2` 分段缓存，之后以 `--invalidate 12-18` 只重渲改动的段落，其余段落直接用缓存。
- 系统测试用：`studio render test-card --mode preview`。
- 输出到 `renders/<项目ID>/<名称>_v00N_preview.mp4`，同目录有 `.json` 渲染记录（代码版本、耗时、尺寸），**永不覆盖**。
- 上传到 Drive：`studio queue run --upload`（需在 `project.yaml` 设定 `drive.previews_folder_id`）。
- 渲染后跑 QC：`studio qc renders/<项目ID>/<文件>.mp4 --project <项目ID>`。

## 7. 如何提交审核

1. Preview 已上传 Drive `06_Project_Previews/`，QC 报告已生成（上传 `08_QC_Reports/`）。
2. 更新交接资讯：`studio project handover <ID> --next-action "请 Reviewer 审核 v003" --issue "第 12 秒配乐稍大"`
3. `studio project status <ID> --set "Awaiting Review" --role Editor --note "v003 请审核"`
4. commit + push。Reviewer 在 GitHub 或 Drive 看到 `HANDOVER.md` 与 Preview。

Reviewer：
- 通过：`studio project status <ID> --set Approved --role Reviewer`
- 退回：`studio project status <ID> --set "Revision Required" --role Reviewer --note "字幕太小、Logo 太晚出现"`

## 8. 如何修改版本

1. `studio project status <ID> --set "In Progress" --role Editor`
2. 按 Reviewer 的 note 修改（代码 / 参数 / 字幕）。
3. 重新生成 Preview —— 自动成为下一个版本号（v004），旧版本保留，可随时比较。
4. 要回到旧版本的**代码**：每个渲染记录 `.json` 都有 `git_commit`，`git checkout <commit>` 即可重现当时的影片。
5. 再次提交审核（第 7 节）。

## 9. 如何输出正式影片

前提：项目状态为 `Approved`。
```bash
studio project status <ID> --set Rendering --role Reviewer
studio queue add --builder <模块>:<函数> --mode final --name <项目ID> --project <项目ID> --upload
studio queue run --upload
studio qc renders/<项目ID>/<项目ID>_v00N_final.mp4 --project <项目ID>
studio project status <ID> --set Completed --role Reviewer
```
- Final 默认：1080×1920、原片帧率、H.264 CRF 16、AAC 256k、**-14 LUFS / -1.5 dBTP**（两段式 loudnorm），可在项目 `overrides` 修改。
- QC 全部 PASS 后上传 `07_Approved_Final_Videos/`。

## 10. 如何交接项目

交接不需要口头说明，**HANDOVER.md 就是交接单**：
```bash
studio project handover <ID> \
  --next-action "替换第二段 B-roll 后提交审核" \
  --todo "确认 CTA 文案" --issue "客户 Logo 的 PNG 解析度不足"
git add projects/<ID> && git commit -m "<ID>: handover" && git push
```
`HANDOVER.md` 自动包含：当前状态、负责人、风格档案、代码版本、最近一次渲染、使用素材、使用模板、待完成事项、已知问题、下一步行动、最近修改记录。
接手的人：`git pull` → `studio project status <ID>`，即可继续。

## 角色权限（`config/roles.yaml`）

| 角色 | 可以 |
|---|---|
| Admin | 全部（含封存、预算、品牌标准） |
| Editor | 开始、提交审核、Preview、交接 |
| Motion Designer | 开始、提交审核、Preview、修改模板、交接 |
| Reviewer | 批准、退回、批准风格档案、正式输出 |
| Viewer | 只读 |

状态流程：Not Started → In Progress → Awaiting Review → (Approved | Revision Required) → Rendering → Completed → Archived。不合法的跳步会被系统拒绝。
